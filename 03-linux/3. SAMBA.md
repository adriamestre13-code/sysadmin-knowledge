# Introducción a SAMBA

Samba es una suite de software de código abierto que implementa el protocolo de red **SMB/CIFS** (*Server Message Block / Common Internet File System*) en sistemas operativos tipo UNIX y Linux. 

Su función principal es permitir la **interoperabilidad y compartición de recursos en redes mixtas**. Gracias a Samba, un servidor Linux (en este caso, Ubuntu Server 26.04 LTS) puede actuar como un servidor de archivos y de impresión nativo para clientes que ejecutan sistemas operativos Windows, permitiendo que estos accedan a carpetas compartidas y gestionen archivos de manera transparente, tal y como lo harían contra un servidor Windows Server.

A través de esta guía paso a paso, se alcanzarán los siguientes objetivos técnicos:

1. **Configuración de conectividad e infraestructura básica:**
   - Establecer la comunicación IP estática entre el servidor Linux (Ubuntu 26.04 LTS) y la máquina cliente (Windows 11 Enterprise) en un entorno virtual aislado.

2. **Gestión de la estructura del servidor Linux:**
   - Crear el árbol de directorios destinado a los recursos compartidos (`/sambaAdria/publica`, `/sambaAdria/oficina` y `/sambaAdria/ASYR1`).
   - Configurar usuarios y grupos del sistema local (`administradores`, `oficina`, `asyr1`) con sus respectivas Listas de Control de Acceso (ACL) y permisos del sistema de archivos.

3. **Despliegue y administración del servicio SAMBA:**
   - Instalar e inicializar el demonio de SAMBA en el servidor.
   - Editar y parametrizar el archivo de configuración `/etc/samba/smb.conf` estableciendo los niveles de acceso (lectura/escritura, invitados, usuarios válidos).
   - Dar de alta a los usuarios en la base de datos de contraseñas de SAMBA (`smbpasswd`).

4. **Validación y auditoría desde el cliente Windows:**
   - Conectar unidades de red en Windows 11 utilizando diferentes credenciales para verificar la correcta aplicación de los permisos.
   - Auditar desde el servidor las conexiones SMB activas para garantizar la trazabilidad del acceso.

## 1. Configuración de los Nombres de Equipo y Red

### 1.1. Configuración en el Servidor (Ubuntu 22.04 LTS)

1. **Adaptador de Red y Dirección IP Estática:**
   * En VirtualBox, asegúrate de que el adaptador de red de la máquina virtual esté en modo **Red interna** (*intnet*) o **Solo-anfitrión** (*Host-only*).
   * Dentro de Ubuntu, dirígete a **Configuración > Red** (*Settings > Network*), edita el perfil de red de la interfaz cableada (*Wired*) e introduce la siguiente configuración IP manual:
     * **Método IPv4:** Manual
     * **Dirección IP:** `192.168.56.20`
     * **Máscara de subred:** `255.255.255.0` (o `/24`)

3. **Verificación en Terminal:**
   * Abre una terminal y ejecuta el siguiente comando para confirmar que la interfaz tiene asignada la dirección IP correcta:
     ```bash
     ip a
     ```

### 1.2. Configuración en el Cliente (Windows 11 Enterprise)

1. **Adaptador de Red y Dirección IP Estática:**
   * Asigna el mismo tipo de red en la configuración de la máquina virtual (*Red interna* o *Solo-anfitrión*).
   * En Windows, abre las **Conexiones de red** (`ncpa.cpl`), edita las propiedades de **Propiedades de Protocolo de Internet versión 4 (TCP/IPv4)** y establece los datos estáticos:
     * **Dirección IP:** `192.168.56.10` (o cualquier dirección dentro del rango `192.168.56.X` distinta a la del servidor)
     * **Máscara de subred:** `255.255.255.0`

2. **Verificación en Consola:**
   * Abre la consola de comandos (`cmd`) y comprueba la configuración de red con:
     ```cmd
     ipconfig
     ```

# Paso 2: Gestión de la Estructura del Servidor Linux

En este paso configuraremos la estructura de directorios que se compartirán mediante SAMBA, la creación de los grupos y usuarios locales en el sistema operativo Ubuntu Server/Desktop (SAMBAGuerrero), y la asignación de permisos adecuados mediante los comandos del sistema y Listas de Control de Acceso (ACL).

## 1. Creación del Árbol de Directorios

Primero, creamos el directorio raíz para los recursos compartidos en la raíz del sistema de archivos y las subcarpetas requeridas según las especificaciones del laboratorio:

1. **Directorio principal y subcarpetas:**
   * /sambaGuerrero (directorio raíz del recurso)
   * /sambaGuerrero/publica (recurso público)
   * /sambaGuerrero/oficina (recurso para el departamento de oficina)
   * /sambaGuerrero/ASYR1 (recurso exclusivo de usuario)

2. **Comandos de creación:**
   sudo mkdir /sambaGuerrero
   sudo mkdir /sambaGuerrero/publica
   sudo mkdir /sambaGuerrero/oficina
   sudo mkdir /sambaGuerrero/ASYR1

## 2. Creación de Grupos y Usuarios Locales

Creamos los grupos locales del sistema y los usuarios asociados a cada departamento o función.

### 2.1. Grupo y Usuario para Administradores

1. Creamos el grupo administradores:
   sudo addgroup administradores

2. Añadimos el usuario root o el usuario principal de administración al grupo administradores:
   sudo usermod -aG administradores root

### 2.2. Grupo y Usuario oficina

1. Creamos el grupo oficina:
   sudo addgroup oficina

2. Creamos el usuario oficina asignándolo directamente a su grupo principal oficina:
   sudo adduser --ingroup oficina oficina

### 2.3. Grupo y Usuario asyr1

1. Creamos el grupo asyr1:
   sudo addgroup asyr1

2. Creamos el usuario asyr1 asignándolo a su grupo principal asyr1:
   sudo adduser --ingroup asyr1 asyr1

## 3. Asignación de Permisos y Listas de Control de Acceso (ACL)

Para garantizar un control preciso sobre quién puede leer o escribir en cada directorio, aplicamos permisos del sistema y reglas de ACL (setfacl).

### 3.1. Permisos en la Carpeta Pública (/sambaGuerrero/publica)
* Requisito: Cualquiera puede acceder (lectura), pero solo los miembros del grupo administradores pueden escribir.

   sudo chown -R root:administradores /sambaGuerrero/publica
   sudo chmod 775 /sambaGuerrero/publica
   sudo setfacl -m g:administradores:rwx /sambaGuerrero/publica
   sudo setfacl -m o::r-x /sambaGuerrero/publica

### 3.2. Permisos en la Carpeta Oficina (/sambaGuerrero/oficina)
* Requisito: Solo los miembros de los grupos oficina y administradores pueden acceder y escribir.

   sudo chown -R root:oficina /sambaGuerrero/oficina
   sudo chmod 770 /sambaGuerrero/oficina
   sudo setfacl -m g:oficina:rwx /sambaGuerrero/oficina
   sudo setfacl -m g:administradores:rwx /sambaGuerrero/oficina
   sudo setfacl -m o::--- /sambaGuerrero/oficina

### 3.3. Permisos en la Carpeta ASYR1 (/sambaGuerrero/ASYR1)
* Requisito: Solo puede acceder el usuario asyr1 (y los administradores para tareas de gestión).

   sudo chown -R asyr1:asyr1 /sambaGuerrero/ASYR1
   sudo chmod 700 /sambaGuerrero/ASYR1
   sudo setfacl -m u:asyr1:rwx /sambaGuerrero/ASYR1
   sudo setfacl -m g:administradores:rwx /sambaGuerrero/ASYR1
   sudo setfacl -m o::--- /sambaGuerrero/ASYR1

## 4. Verificación de Permisos Locales

Comprobamos que las reglas de permisos se hayan aplicado correctamente mediante el comando getfacl:

1. Verificar la carpeta pública:
   getfacl /sambaGuerrero/publica

2. Verificar la carpeta oficina:
   getfacl /sambaGuerrero/oficina

3. Verificar la carpeta ASYR1:
   getfacl /sambaGuerrero/ASYR1

4. Prueba de denegación local:
   Cambiamos al usuario asyr1 mediante "su - asyr1" e intentamos acceder a la carpeta oficina:
   su - asyr1
   cd /sambaGuerrero/oficina
   (El sistema debe devolver error de acceso denegado).
