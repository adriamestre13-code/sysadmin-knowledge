# Introducción a SAMBA

Samba es una suite de software de código abierto que implementa el protocolo de red **SMB/CIFS** (*Server Message Block / Common Internet File System*) en sistemas operativos tipo UNIX y Linux. 

Su función principal es permitir la **interoperabilidad y compartición de recursos en redes mixtas**. Gracias a Samba, un servidor Linux (en este caso, Ubuntu Server 26.04 LTS) puede actuar como un servidor de archivos y de impresión nativo para clientes que ejecutan sistemas operativos Windows, permitiendo que estos accedan a carpetas compartidas y gestionen archivos de manera transparente, tal y como lo harían contra un servidor Windows Server.

   - Instalar e inicializar el demonio de SAMBA en el servidor.

4. **Validación y auditoría desde el cliente Windows:**
   - Conectar unidades de red en Windows 11 utilizando diferentes credenciales para verificar la correcta aplicación de los permisos.
   - Auditar desde el servidor las conexiones SMB activas para garantizar la trazabilidad del acceso.

## 2. Creación de Grupos y Usuarios Locales

Creamos los grupos locales del sistema y los usuarios asociados a cada departamento o función.

### 2.1. Grupo y Usuario para Administradores

1. Creamos el grupo administradores:
   `sudo addgroup administradores`
2. Añadimos el usuario root o el usuario principal de administración al grupo administradores:
   `sudo usermod -aG administradores root`

### 2.2. Grupo y Usuario oficina

1. Creamos el grupo oficina:
   `sudo addgroup oficina`
2. Creamos el usuario oficina asignándolo directamente a su grupo principal oficina:
   `sudo adduser --ingroup oficina oficina`

### 2.3. Grupo y Usuario asyr1

1. Creamos el grupo asyr1:
   `sudo addgroup asyr1`
2. Creamos el usuario asyr1 asignándolo a su grupo principal asyr1:
   `sudo adduser --ingroup asyr1 asyr1`
   
## 3. Asignación de Permisos y Listas de Control de Acceso (ACL)

Para garantizar un control preciso sobre quién puede leer o escribir en cada directorio, aplicamos permisos del sistema y reglas de ACL (setfacl).

* Requisito: Cualquiera puede acceder (lectura), pero solo los miembros del grupo administradores pueden escribir.

   sudo chmod 775 /sambaGuerrero/publica
   sudo setfacl -m g:administradores:rwx /sambaGuerrero/publica
   sudo setfacl -m o::r-x /sambaGuerrero/publica

# Paso 3: Despliegue y Administración del Servicio SAMBA

En este bloque abordaremos la instalación, configuración y puesta en marcha del servidor SAMBA en el equipo Ubuntu (`SAMBAAdria`), la definición de los recursos compartidos con sus parámetros específicos, la gestión de usuarios en la base de datos de SAMBA y la posterior comprobación de su funcionamiento.

## 1. Instalación del Servidor SAMBA

1. **Cambio temporal de red a modo NAT:**
   * Para poder descargar e instalar los paquetes necesarios desde los repositorios de Ubuntu, cambia temporalmente el adaptador de red de la máquina virtual de *Red interna* / *Host-only* a modo **NAT**.

2. **Actualización e instalación del servicio:**
   * Ejecuta los siguientes comandos en la terminal de Ubuntu para actualizar la lista de paquetes e instalar SAMBA:
     `sudo apt update`
     `sudo apt install -y samba`

3. **Verificación del estado del servicio:**
   * Comprueba que los demonios de SAMBA (`smbd` y `nmbd`) se han instalado e iniciado correctamente:
     `sudo systemctl status smbd`
>
> <img width="971" height="608" alt="image" src="https://github.com/user-attachments/assets/949bf7bb-43cc-40b1-aca9-3d20c7e5f03c" />

4. **Restablecimiento de la red local:**
   * Vuelve a cambiar la red de la máquina virtual al modo **Red interna** (o *Host-only*).
   * Verifica la conectividad con el cliente Windows ejecutando de nuevo un `ping 192.168.56.10`.

## 2. Configuración del Fichero `/etc/samba/smb.conf`

Editamos el archivo principal de configuración de SAMBA para definir los tres recursos compartidos (`publica`, `oficina` y `ASYR1`).

1. **Copia de seguridad del archivo original:**
   `sudo cp /etc/samba/smb.conf /etc/samba/smb.conf.bak`

2. **Edición del fichero:**
   Abre el archivo con un editor de texto:
   `sudo nano /etc/samba/smb.conf`

3. **Añadir las definiciones de las carpetas compartidas al final del archivo:**

   ```cmd
   [publica]
   comment = carpeta pública (Comentario acerca de la carpeta)
   path = /sambaAdria/publica
   browseable = yes
   guest ok = yes
   writable = yes
   write list = @administradores

   [oficina]
   comment = carpeta oficina (Comentario acerca de la carpeta)
   path = /sambaAdria/oficina
   browseable = yes
   guest ok = yes
   writable = yes
   write list = @oficina, @administradores
   valid users = @oficina, @administradores

   [ASYR1]
   comment = carpeta ASYR1 (Comentario acerca de la carpeta)
   path = /sambaAdria/ASYR1
   browseable = yes
   guest ok = yes
   writable = no
   valid users = asyr1
   ```
>
> <img width="969" height="608" alt="image" src="https://github.com/user-attachments/assets/1dba62ba-0f4e-4673-8ef3-5f1fd6b931af" />

4. **Explicación de los parámetros utilizados:**
   * **[nombre_recurso]:** Nombre con el que se mostrará la carpeta compartida en la red.
   * **comment:** Descripción informativa sobre el recurso compartido.
   * **path:** Ruta absoluta del directorio físico en el servidor Linux.
   * **browseable = yes:** Permite que la carpeta sea visible al explorar el servidor desde la red.
   * **guest ok = yes:** Permite la conexión inicial como usuario invitado/anónimo.
   * **writable = yes / no:** Establece la capacidad de modificación global del recurso compartidos.
   * **write list:** Lista de usuarios o grupos (precedidos por `@`) con permisos explícitos de escritura.
   * **valid users:** Lista de usuarios o grupos autorizados a acceder al recurso. Cualquier otro usuario tendrá el acceso denegado.

## 3. Creación de Usuarios en la Base de Datos de SAMBA

Para que los usuarios puedan autenticarse desde los clientes en red, es necesario registrarlos en la base de datos de credenciales de SAMBA (`smbpasswd`).

1. **Alta del usuario administrador (root / administrador):**
   `sudo smbpasswd -a root`
2. **Alta del usuario oficina:**
   `sudo smbpasswd -a oficina`
3. **Alta del usuario asyr1:**
   `sudo smbpasswd -a asyr1`

## 4. Reinicio del Servicio y Verificación de la Configuración

1. **Comprobar la sintaxis del archivo de configuración:**
   Ejecuta la herramienta de diagnóstico de SAMBA para verificar que no existan errores sintácticos en `/etc/samba/smb.conf`:
   `testparm`

2. **Reiniciar los servicios de SAMBA para aplicar los cambios:**
   `sudo systemctl restart smbd`
   `sudo systemctl restart nmbd`

## 3. Auditoría de Conexiones Activas en el Servidor SAMBA

Desde la máquina Ubuntu (`SAMBAAdria`), es posible inspeccionar en tiempo real qué clientes y usuarios están conectados al servidor, qué recursos están utilizando y qué archivos mantienen abiertos.

1. **Comando de auditoría:**
   Ejecuta la herramienta de monitoreo de SAMBA en la terminal del servidor:
   `sudo smbstatus`
> <img width="971" height="607" alt="image" src="https://github.com/user-attachments/assets/5e454f19-db22-4757-ab6e-85fc56b3592a" />

2. **Análisis de la salida del comando:**
   El comando `smbstatus` muestra la información estructurada en tres secciones principales:
   * **Samba version & Service:** Muestra la versión instalada del servicio y los demonios activos.
   * **PID / Username / Group / Machine / Protocol Version:** Lista las sesiones establecidas, indicando la dirección IP del cliente Windows (`192.168.56.10`), el nombre del equipo (`CLIENTEAdria`), el PID del proceso asignado y el nombre del usuario autenticado (`root`, `oficina` o `asyr1`).
   * **Service / pid / Machine / Connected at:** Muestra a qué carpetas compartidas concretas (`publica`, `oficina`, `ASYR1`) está accediendo cada sesión y desde qué momento.
   * **Locked files:** Muestra los archivos abiertos o bloqueados en ese instante por los clientes en red.
