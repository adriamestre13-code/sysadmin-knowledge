# Gestión de Particiones y Almacenamiento en Ubuntu Desktop

En entornos GNU/Linux, la gestión del almacenamiento difiere de la estructura habitual basada en letras de unidad de Windows. Linux organiza las particiones dentro de un árbol de directorios único jerárquico donde cada sección del disco se monta sobre un punto específico de la estructura del sistema de archivos.

---

### 1. ¿Para qué sirven las particiones en Linux?

* **Aislamiento del Directorio Raíz (`/`) y Datos (`/home`):** Separar el sistema operativo de los archivos personales permite reinstalar o actualizar la distribución sin afectar a los documentos, configuraciones y datos de los usuarios.
* **Espacio de Intercambio (SWAP):** Permite reservar una partición o archivo dedicado a la memoria virtual cuando la memoria RAM física se satura o se requiere hibernación del sistema.
* **Seguridad y Cuotas de Disco:** Aislar directorios críticos como `/var` o `/tmp` evita que logs de aplicaciones o archivos temporales consuman todo el espacio del sistema principal y provoquen un fallo global.
* **Gestión de Múltiples Sistemas de Archivos:** Permite utilizar formatos nativos como Ext4 junto a otros como FAT32 o NTFS para compartir datos con sistemas Windows.

---

### 2. Estructura de Nombrado y Sistemas de Archivos

A diferencia de las asignaciones por letras (`C:`, `D:`), Linux representa cada disco y partición como un archivo especial dentro del directorio `/dev`:

#### A. Identificación de Dispositivos en `/dev`
* **SATA / IDE / SCSI:** Se nombran como `sdX` donde `X` representa la letra del disco físico (`sda` para el primer disco, `sdb` para el segundo, etc.).
* **Particiones:** Se identifican agregando un número al final del disco (`sdb1`, `sdb2`, `sdb5`).
  * En tablas MBR, las particiones primarias/extendidas se numeran del **1 al 4** (`sdb1` a `sdb4`).
  * Las unidades lógicas dentro de una partición extendida comienzan siempre a partir de **`sdb5`**.

#### B. Sistemas de Archivos Principales
* **Ext4 (Fourth Extended Filesystem):** Es el estándar nativo en Ubuntu. Ofrece alto rendimiento, registro transaccional (*journaling*) y excelente estabilidad.
* **SWAP:** Área especial formateada para uso exclusivo del kernel como memoria virtual suplementaria.

##### 2.1. Creación de la Tabla de Particiones (`fdisk`)

Abrimos la herramienta de edición de tablas MBR/DOS para el disco `/dev/sdb`:

```bash
sudo fdisk /dev/sdb
```
>
> <img width="971" height="608" alt="image" src="https://github.com/user-attachments/assets/764379c0-1e89-4ee3-93b7-d0c61d0b7d74" />

Dentro del menú interactivo de `fdisk`, ejecutamos las siguientes secuencias:

##### A. Particiones Primarias
1. **Crear `/dev/sdb1` (10 GB):**
   * Presionar `n` $\rightarrow$ `p` (primaria) $\rightarrow$ Número `1` $\rightarrow$ Primer sector (por defecto) $\rightarrow$ Último sector: `+10G`
2. **Crear `/dev/sdb2` (15 GB):**
   * Presionar `n` $\rightarrow$ `p` (primaria) $\rightarrow$ Número `2` $\rightarrow$ Primer sector (por defecto) $\rightarrow$ Último sector: `+15G`
   >
   > <img width="972" height="608" alt="image" src="https://github.com/user-attachments/assets/a32dded3-6c5c-41be-85cc-47305fdb3c63" />

##### B. Partición Extendida y Unidades Lógicas
1. **Crear la Partición Extendida (Resto del disco):**
   * Presionar `n` $\rightarrow$ `e` (extendida) $\rightarrow$ Número `3` $\rightarrow$ Primer sector (por defecto) $\rightarrow$ Último sector (por defecto para ocupar el espacio restante).
2. **Crear `/dev/sdb5` (2 GB - SWAP):**
   * Presionar `n` $\rightarrow$ Tipo Lógica (asignado por defecto) $\rightarrow$ `+2G`
   * Cambiar tipo a SWAP: Presionar `t` $\rightarrow$ Selección `5` $\rightarrow$ Código `82` (Linux swap)
3. **Crear `/dev/sdb6` (8 GB):**
   * Presionar `n` $\rightarrow$ `+8G`
4. **Crear `/dev/sdb7` (5 GB):**
   * Presionar `n` $\rightarrow$ `+5G`
5. **Crear `/dev/sdb8` (10 GB):**
   * Presionar `n` $\rightarrow$ `+10G`

##### 2.3. Creación de Puntos de Montaje y Montaje Manual

Creamos los directorios de destino dentro de la raíz `/` y asociamos los dispositivos físicos:

```bash
# Crear directorios para los puntos de montaje
sudo mkdir -p /copia /imagen /datos /datos1 /datos2

# Montar particiones de datos
sudo mount /dev/sdb1 /datos1
sudo mount /dev/sdb2 /datos2
sudo mount /dev/sdb6 /copia
sudo mount /dev/sdb7 /imagen
sudo mount /dev/sdb8 /datos

# Activar la partición SWAP
sudo swapon /dev/sdb5
```

##### 2.5. Configuración del Archivo `/etc/fstab`

El archivo `/etc/fstab` define qué dispositivos se montan automáticamente al arrancar el sistema.

###### A. Estructura de cada línea en `/etc/fstab`

Cada entrada contiene 6 campos separados por espacios o tabuladores:

```text
[Dispositivo/UUID]  [Punto de montaje]  [Sistema de archivos]  [Opciones]  [Dump]  [Pass]
```

1. **Dispositivo / UUID:** Identificador único del volumen (`UUID=...`) o ruta `/dev/sdX`.
2. **Punto de montaje:** Directorio raíz donde se integra la partición (ej. `/copia`).
3. **Sistema de archivos:** Protocolo utilizado (`ext4`, `swap`, `ntfs`, etc.).
4. **Opciones:** Parámetros de montaje (`defaults` asigna `rw`, `suid`, `dev`, `exec`, `auto`, `nouser`, `async`).
5. **Dump (0/1):** Utilizado por la herramienta de respaldo `dump`. `0` desactiva la copia de seguridad.
6. **Pass (0/1/2):** Orden de revisión del disco por `fsck` durante el arranque. `1` para la raíz `/`, `2` para otras particiones, `0` para desactivar la comprobación.

###### B. Añadir las entradas al fichero

Editamos el archivo de configuración:

```bash
sudo nano /etc/fstab
```

Añadimos al final del documento las siguientes líneas:

```text
# Particiones del disco secundario /dev/sdb
/dev/sdb1    /datos1    ext4    defaults    0    2
/dev/sdb2    /datos2    ext4    defaults    0    2
/dev/sdb5    none       swap    sw          0    0
/dev/sdb6    /copia     ext4    defaults    0    2
/dev/sdb7    /imagen    ext4    defaults    0    2
/dev/sdb8    /datos     ext4    defaults    0    2
```

##### 2.6. Reinicio y Verificación del Montaje Automático

Probamos el archivo `/etc/fstab` antes de reiniciar para descartar errores sintácticos que impidan el arranque:

```bash
sudo mount -a
```

Reiniciamos el sistema operativo:

```bash
sudo reboot
```

Una vez iniciada la sesión, confirmamos que todas las particiones se han montado automáticamente en el arranque:

```bash
lsblk
```
