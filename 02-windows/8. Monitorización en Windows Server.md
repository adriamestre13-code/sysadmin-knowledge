# Monitorización y auditorias en Windows Server

La monitorización y la auditoría de sistemas son pilares fundamentales dentro de la administración de infraestructura IT y la ciberseguridad. En entornos empresariales, no basta con desplegar servicios y aplicar configuraciones de almacenamiento o respaldos; es imprescindible disponer de visibilidad en tiempo real y registro histórico de los sucesos que ocurren en los servidores y clientes del dominio.

En esta sección abordaremos las herramientas nativas del entorno Windows (Windows Server 2022 y clientes Windows 11 Pro/Enterprise) para el análisis de registros, la auditoría de accesos a recursos y la centralización de eventos del sistema.

---

## ¿Por qué es importante?

1. **Detección y resolución de problemas (Troubleshooting):** Permite diagnosticar fallos de hardware, errores en servicios del sistema o anomalías de software mediante el análisis de registros (*logs*).
2. **Seguridad y Ciberseguridad:** Facilita la identificación de accesos no autorizados, intentos de inicio de sesión erróneos, modificaciones indebidas en grupos de seguridad o manipulación no permitida de archivos.
3. **Cumplimiento normativo y forense:** Garantiza un registro inalterable de la actividad de los usuarios y objetos del dominio, requisito esencial para auditar la explotación de recursos informáticos.
4. **Administración centralizada:** Evita la revisión manual equipo por equipo permitiendo la recolección automática de eventos críticos de los clientes hacia un único punto de control.

---

## Objetivos del Laboratorio de Monitorización

Al finalizar esta sección del documento técnico en GitHub, se habrán cumplido y documentado los siguientes objetivos prácticos:

- **Análisis de Logs del Sistema (Visor de Eventos):** Identificar, categorizar y documentar registros de Aplicación, Seguridad, Instalación y Sistema en un entorno Windows Server 2022 o cliente Windows 11 Pro/Enterprise, analizando errores específicos y detallando su procedimiento de resolución.
- **Seguridad y Auditoría de Usuarios:** Configurar directivas de grupo (GPO) para auditoría de eventos de inicio de sesión, administración de cuentas y acceso a objetos, además de establecer restricciones de complejidad y bloqueo de contraseñas.
- **Auditoría granular de recursos compartidos:** Implementar entradas de auditoría de seguridad sobre carpetas y archivos compartidos (`\\SRVTunombre\Public`) para auditar la creación, modificación y eliminación de contenido.
- **Centralización y Suscripción de Eventos:** Configurar el servicio WinRM (*Windows Remote Management*) en los equipos cliente para recolectar y reenviar sus registros críticos y de error hacia la consola de Windows Server de manera automatizada.

## Paso 1. Análisis de Logs del Sistema (Visor de Eventos)

El Visor de Eventos (*Event Viewer*) de Windows registra las incidencias del sistema, aplicaciones y seguridad, clasificándolas según su origen y gravedad. ### 1.2. Análisis y resolución de un error de Aplicación

Selecciona un evento de error registrado en el log de **Aplicación** para documentar su origen y el procedimiento de corrección.
>
> <img width="869" height="662" alt="image" src="https://github.com/user-attachments/assets/973ac420-abfb-4030-8212-a456365d42b3" />

- **Error analizado:** Evento 8200 (Fallo en la adquisición de licencia).
- **Causa:** El sistema operativo o una funcionalidad asociada intenta validar o adquirir la licencia del producto sin disponer de una clave de producto válida configurada.
- **Procedimiento de resolución:**
    1. Accede a **Settings -> Update & Security -> Activation** en Windows Server.
    2. Haz clic en **Change Product Key** (Cambiar la clave de producto).
    3. Introduce una clave de licencia válida en la ventana emergente y pulsa **Next** para completar la activación y validar el sistema.

### 1.3. Análisis y resolución de un error de Sistema

Selecciona un evento de error registrado en el log de **Sistema** para documentar su causa y la buena práctica para prevenir su reaparición.
>
> <img width="869" height="662" alt="image" src="https://github.com/user-attachments/assets/a4ffc84b-0e16-4403-8f59-f7ef0d0d52bf" />

- **Error analizado:** Evento 6008 (Apagado no esperado del sistema).
- **Causa:** Ocurre cuando el servidor sufre un apagado repentino, un corte de energía o un reinicio forzado sin completar la secuencia de cierre adecuada.
- **Procedimiento de prevención/resolución:**
    1. Evita el apagado o reinicio mediante el botón físico de encendido/apagado de la máquina física o virtual.
    2. Realiza siempre un apagado controlado accediendo al menú **Start -> Power -> Shut down**.
    3. En servidores Windows, selecciona la razón adecuada en el menú emergente (*Shut Down Event Tracker*, ej. *Other Unplanned* o *Operating System: Reconfiguration*) y presiona **Continue** para permitir un cierre limpio de servicios y registros.

### 2.2. Configuración de la política de contraseñas y bloqueo de cuentas

Accede al editor de directivas de grupo (**Group Policy Management Editor**) editando la directiva `Default Domain Policy` (`Computer Configuration -> Policies -> Windows Settings -> Security Settings -> Account Policies`):
>
> <img width="869" height="662" alt="image" src="https://github.com/user-attachments/assets/5304fa3b-80fc-45e6-931a-40313f0af20d" />

1. **Política de contraseñas (Password Policy):**
    - **Minimum password length**: 12 caracteres.
    - **Maximum password age**: 95 días.
    - **Password must meet complexity requirements**: Enabled.
    - *Explicación de requisitos de complejidad*: Las contraseñas deben contener al menos 6 caracteres y combinar al menos 3 de las siguientes 4 categorías: mayúsculas, minúsculas, números y caracteres especiales, sin incluir el nombre de cuenta.
    - **Comprobación**: Intenta cambiar la contraseña de un usuario a una versión simple de 9 caracteres (ej. `123456789`). La consola o línea de comandos debe denegar el cambio mostrando un mensaje de incumplimiento de directiva.

2. **Política de bloqueo de cuenta (Account Lockout Policy):**
    - **Account lockout duration**: 1 minuto.
    - **Account lockout threshold**: 3 intentos fallidos de inicio de sesión.
    - **Reset account lockout counter after**: 1 minuto.
    - **Comprobación**: Introduce 3 veces consecutivas una contraseña incorrecta al iniciar sesión en el cliente Windows 11 con el usuario `boss`. Confirma que el sistema bloquea la cuenta con el mensaje de advertencia (Para que se apliquen las políticas escribe en la CMD ``gpupdate /force``).

### 2.3. Configuración de la auditoría de seguridad del dominio

1. En la directiva `Default Domain Policy`, navega hasta `Computer Configuration -> Policies -> Windows Settings -> Security Settings -> Local Policies -> Audit Policy`.
2. Habilita las siguientes auditorías para registrar eventos de éxito y fallo (**Success** y **Failure**):
    - **Audit account logon events** (Auditoría de eventos de inicio de sesión de cuentas).
    - **Audit account management** (Auditoría de administración de cuentas).
    - **Audit object access** (Auditoría de acceso a objetos).
3. Fuerza la actualización inmediata de la directiva de grupo en el servidor ejecutando en la consola CMD:

    gpupdate /force

### 2.4. Auditoría de eventos de inicio de sesión de usuarios

1. En el cliente Windows 11 Pro, realiza intentos de inicio de sesión correctos e incorrectos utilizando las cuentas `usuario1` y `usuario2`.
2. Accede al **Visor de Eventos** de Windows Server en el apartado **Windows Logs -> Security**.
3. Localiza y verifica los registros correspondientes:
    - **Event ID 4624**: Inicio de sesión correcto.
    - **Event ID 4625** / **4771**: Intento de inicio de sesión fallido (error de autenticación).

### 2.5. Auditoría de administración de usuarios y grupos

1. Abre la herramienta **ADAC** en el servidor y realiza la creación de dos nuevos usuarios en la UO `Usuarios`: `usuario3` y `usuario4`.
2. Crea dos grupos de seguridad globales en la UO `Grupos`: `Grupo1` y `Grupo2`.
3. Asigna miembros a los grupos:
    - Agrega `usuario1` al `Grupo1`.
    - Agrega `usuario2` al `Grupo2`.
4. Elimina del directorio las cuentas `usuario4` y `usuario5` (si estuviese presente).
5. Comprueba en el **Visor de Eventos -> Security** de Windows Server la generación de logs por cada acción:
    - **Event ID 4720**: Creación de usuario.
    - **Event ID 4726**: Eliminación de usuario.
    - **Event ID 4727**: Creación de grupo de seguridad.
    - **Event ID 4728**: Adición de un usuario a un grupo de seguridad.

### 2.6. Auditoría de acceso a recursos compartidos (Carpeta Public)

1. En la unidad del servidor donde se ubica la carpeta compartida pública (`\\SRVTuapellido\Public`), abre las **Propiedades** del recurso -> pestaña **Seguridad** -> botón **Opciones avanzadas** -> pestaña **Auditoría**.
2. Haz clic en **Agregar** y configura la entrada de auditoría para la entidad de seguridad `Usuarios del dominio` (`Domain Users`):
    - **Tipo**: Todos (*All*).
    - **Se aplica a**: Esta carpeta, subcarpetas y archivos.
    - **Permisos avanzados**: Marca las casillas de *Crear archivos / escribir datos*, *Crear carpetas / anexar datos*, *Eliminar subcarpetas y archivos* y *Eliminar*.
3. Aplica los cambios y fuerza la actualización de directivas en servidor y cliente:

    gpupdate /force

4. **Ejecución de pruebas en el cliente**:
    - Inicia sesión en el cliente con `usuario2`.
    - Accede vía Explorador de archivos a `\\SRVTuapellido\Public`.
    - Crea una carpeta llamada `Auditar`.
    - Dentro de la carpeta, crea dos archivos de texto: `Auditando.txt` y `TuNombreapellido.txt`.
    - Procede a eliminar ambos archivos `.txt`.
    - Cierra la sesión de usuario.

5. **Verificación de logs de archivo**:
    - En Windows Server, abre el **Visor de Eventos -> Security**.
    - Filtra o localiza los registros de acceso al sistema de archivos:
        - **Event ID 4663**: Intento de acceso a un objeto (creación de archivos/carpetas).
        - **Event ID 4660**: Eliminación efectiva de un objeto del sistema de archivos.
