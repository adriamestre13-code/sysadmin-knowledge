# Conectividad de Red entre Equipos (Windows y Linux)

La interconexión de sistemas operativos heterogéneos es un pilar fundamental en la administración de sistemas. Configurar de forma manual la dirección IP, la máscara de subred y probar la comunicación mediante tramas de red permite establecer canales de comunicación directos entre clientes y servidores dentro de un segmento local aislado.

Este laboratorio aborda la configuración de parámetros de red estáticos en una máquina virtual con Windows 11 Enterprise para garantizar la conectividad punto a punto con otro sistema dentro de una red privada.

### Objetivos del laboratorio

* **Asignación de Parámetros de Red:** Configurar manualmente direcciones IP privadas estáticas y máscaras de subred.
* **Gestión Multicanal (GUI / CLI):** Aplicar configuraciones de red tanto desde el entorno gráfico como desde la consola de comandos mediante la utilidad `netsh`.
* **Verificación de Conectividad:** Diagnosticar la resolución de direcciones y la conectividad lógica entre máquinas virtuales.

---

### Fundamentos Teóricos: Funcionamiento de las Redes Locales

Para que dos equipos puedan comunicarse dentro de una misma red local (LAN) sin necesidad de pasar por un enrutador o salir a Internet, deben cumplir las siguientes condiciones:

1. **Segmento de red común:** Ambas máquinas deben tener direcciones IP dentro del mismo rango definido por la máscara de subred (por ejemplo, en un rango `192.168.56.0/24`, los IPs varían entre `192.168.56.1` y `192.168.56.254`).
2. **Modo de red en la máquina virtual:** Debe utilizarse el modo **Red Interna** (*Internal Network*) o **Solo-Anfitrión** (*Host-Only*). Este modo crea un conmutador (*switch*) virtual donde las máquinas enviarán y recibirán tramas Ethernet de forma aislada.
3. **Ausencia de puerta de enlace y DNS:** Al ser una comunicación directa en capa 2/3 dentro del mismo segmento local, no se requiere configurar una Puerta de Enlace (*Default Gateway*) ni Servidores DNS, ya que no existe tráfico que deba salir fuera de la red.

### 1. Configuración de IP Estática en Windows 11 Pro

Para este ejemplo, utilizaremos el rango privado `192.168.56.0/24` y asignaremos a la máquina de Windows la IP `192.168.56.10` con máscara `255.255.255.0`.

#### A. Configuración desde la Interfaz Gráfica (GUI)

1. Abrimos el menú **Ejecutar** (`Windows + R`), escribimos `ncpa.cpl` y pulsamos **Enter** para abrir las *Conexiones de red*.
2. Hacemos clic derecho sobre la tarjeta de red (por ejemplo, *Ethernet*) y seleccionamos **Propiedades**.
3. En la lista, seleccionamos **Protocolo de Internet versión 4 (TCP/IPv4)** y hacemos clic en **Propiedades**.
4. Marcamos la opción **Usar la siguiente dirección IP** e introducimos:
   * **Dirección IP:** `192.168.100.10`
   * **Máscara de subred:** `255.255.255.0`
   * **Puerta de enlace predeterminada:** *(En blanco)*
5. Dejamos vacíos los campos de DNS y hacemos clic en **Aceptar** > **Cerrar**.

#### B. Configuración desde la Consola de Comandos (`netsh`)

1. Abrimos la consola de comandos (**CMD**) con privilegios de administrador.
2. Identificamos el nombre exacto de la interfaz de red ejecutando:

```cmd
netsh interface ipv4 show interfaces
```

### 2. Configuración de IP Estática en Ubuntu Desktop

Para mantener la comunicación directa con la máquina Windows (`192.168.56.10`), asignaremos a Ubuntu Desktop la dirección IP `192.168.56.20` dentro del mismo rango (`192.168.56.0/24`).

---

#### A. Configuración desde la Interfaz Gráfica (GUI)

1. Abrimos **Configuración** (*Settings*) desde el menú de aplicaciones o el panel superior derecho.
2. En la barra lateral izquierda, seleccionamos **Red** (*Network*).
3. En la sección de la interfaz cableada (*Wired*), hacemos clic en el icono de engranaje (**⚙**) para abrir los ajustes.
4. Vamos a la pestaña **IPv4**.
5. Seleccionamos el método **Manual**.
6. Añadimos la dirección en la tabla de configuración:
   * **Dirección IP:** `192.168.56.20`
   * **Máscara de red:** `255.255.255.0` (o `24`)
   * **Puerta de enlace:** *(En blanco)*

#### B. Configuración desde la Consola mediante Netplan (`/etc/netplan`)

1. Abrimos la terminal (`Ctrl + Alt + T`).
2. Identificamos el nombre exacto de la interfaz de red ejecutando:

```bash
ip a
```

*(Identificamos el nombre de la tarjeta, por ejemplo: `enp0s3` o `eth0`).*

3. Localizamos el archivo de configuración YAML en la carpeta de Netplan:

```bash
ls /etc/netplan/
```
>
> <img width="972" height="608" alt="Captura de pantalla 2026-09-03 234522" src="https://github.com/user-attachments/assets/ab74fe75-44f2-4535-a2a8-b7d882fda94a" />

4. Editamos el archivo de configuración (suele llamarse `01-network-manager-all.yaml` o similar):

```bash
sudo nano /etc/netplan/01-network-manager-all.yaml
```

5. Modificamos el contenido asegurando la sangría correcta (usar espacios, nunca tabuladores):

```yaml
network:
  version: 2
  renderer: NetworkManager
  ethernets:
    enp0s3:
      dhcp4: no
      addresses:
        - 192.168.56.20/24
```

6. Guardamos los cambios (**`Ctrl + O`**, **`Enter`**) y salimos (**`Ctrl + X`**).
7. Aplicamos la nueva configuración ejecutando:

```bash
sudo netplan --debug generate
sudo netplan try
sudo netplan apply
```

#### C. Fundamentos de la Interoperabilidad entre Sistemas Distintos

La comunicación entre Windows 11 y Ubuntu es posible gracias a que la arquitectura de red está basada en **estándares abiertos y universales**, independientemente del sistema operativo o kernel que ejecute cada equipo:

* **Modelo TCP/IP y Estándares IETF:** Ambos sistemas implementan la pila de protocolos TCP/IP definida por la *IETF* (*Internet Engineering Task Force*), garantizando que las estructuras de los datos transmitidos sean idénticas.
* **Capa 2 (Enlace de datos):** Windows y Linux formatean la información en tramas **Ethernet II** estandarizadas que contienen las direcciones físicas (MAC).
* **Capa 3 (Red):** Ambas máquinas estructuran las cabeceras **IPv4** con el mismo formato de 32 bits para el direccionamiento.
* **Protocolo ICMP:** La herramienta `ping` utiliza el protocolo *Internet Control Message Protocol*. Tanto el kernel de Windows como el de Linux interpretan las peticiones de eco (`Echo Request`) y responden con las réplicas (`Echo Reply`) usando la misma sintaxis.
* **Abstracción del Hipervisor:** El conmutador virtual (*Virtual Switch*) de VirtualBox trabaja en Capa 2, conmutando las tramas Ethernet entre las tarjetas virtuales sin importar el sistema operativo huésped.
